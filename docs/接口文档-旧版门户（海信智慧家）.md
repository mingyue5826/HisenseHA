# 接口文档 · 旧版门户（海信智慧家时期）

> 说明：本文记录**门户风格**请求信封、旧版数组状态格式，以及空调/洗衣机时代的命令表。
> 域名 `api-wg.hismarttv.com` 的旧版业务接口本集成**已不再使用**，
> 现在所有设备读写都走 AIHome，但**登录与读接口仍沿用门户风格信封**。
> AIHome 接口见 [`接口文档-AIHome（海信爱家）.md`](./接口文档-AIHome（海信爱家）.md)。

---

## 一、与 AIHome 的关系

| 维度 | 旧版门户（海信智慧家） | AIHome（海信爱家） |
|---|---|---|
| 业务域名 | `api-wg.hismarttv.com` | `iot-aihome.hismarttv.com` |
| 登录域名 | `portal-account.hismarttv.com/mobile/signon` | `portal-account.hismarttv.com/mobile/se/signon` |
| 登录请求体 | 明文 JSON，`json=data` | **AES 密文**，`data=body` + `appKey` + `X-Sign-For` |
| 状态模型 | **定长逗号数组**（空调 210 项 / 冰箱 130 项） | **命名键值对** `device.states` |
| 控制模型 | 数组下标赋值 | `command + params` 命名式动作 |
| 返回 token | `tokenInfo.token` / `refreshToken` | 同上，多了 `customerId` |
| 刷新链路 | `bas-wg.hismarttv.com/aaa/refresh_token2` | 无，直接重新登录 |

**迁移要点**：登录换成 `/mobile/se/signon` + 加密签名后，`accessToken` 变为长期有效，
所以"刷新 token"退化成"用账号密码重登"。

## 二、认证（门户风格）

AIHome 与旧版共用同一个账号体系，登录接口已升级为加密版，完整字段见
[`接口文档-AIHome` 第一节](./接口文档-AIHome（海信爱家）.md)。

关键差异表：

| 项 | 旧版 | 现用 |
|---|---|---|
| 路径 | `/mobile/signon` | `/mobile/se/signon` |
| 请求体传参 | `json=data`（作为 JSON） | `data=body`（作为**字符串**） |
| 请求头 | 无特殊 | `appKey: commonweb`、`X-Sign-For: base64(MD5(body+secret))` |
| `loginName` / `signature` | 明文 | AES-256-CBC + base64 |
| `adaptertRank` | `3098` / `4130` | `720` |
| 多余字段 | `pdateTime` / `version` / `deviceType` / `appType` 塞在 body | body 只留 5 字段，其余移到 query |

### 加密函数（伪代码）

```
ENC(v)  = base64( AES-256-CBC( v, key=SECRET, iv=SECRET[:16], PKCS7 ) )
SIGN(b) = base64( MD5( b + SECRET ) )

SECRET = "MORZRbkuiWxjp+SM4vR_GxY4pZxLZ6rn"
```

> `SECRET` 是 32 字符 → AES 取 32 字节 = AES-256；IV 固定取前 16 字符。
> 签名对象是**最终发送的那串 JSON 字符串**，不是对象，也不能重新序列化。

## 三、门户风格读请求信封

所有读接口（`home/list`、`devices/list`、`devices/detail`）共用同一信封，
只有 `payload` 里多几个字段。

### 请求头

| 请求头 | 值 |
|---|---|
| `Content-Type` | `application/json; charset=UTF-8` |
| `Accept` | `application/json` |
| `User-Agent` | `okhttp/4.10.0` |
| `appKey` | `commonweb` |
| `X-Sign-For` | `base64(MD5(body + secret))` |

### 请求体信封

| 字段 key | 类型 | 固定值 / 示例 | 说明 |
|---|---|---|---|
| `lastUpdateTime` | int | `0` | 0 = 全量 |
| `accessToken` | string | | 登录返回 |
| `appVersion` | string | `""` | 读接口填空串 |
| `openId` | string | `""` | 固定空 |
| `version` | string | `"1.0"` | 固定 |
| `deviceType` | int | `2` | 手机 |
| `appType` | int | `100` | 门户 App 类型 |
| `versionCode` | string | `"101"` | 固定 |
| `adaptertRank` | int | `720` | 固定 |
| `_` | int | `1792279336082` | 毫秒时间戳 |
| `header.messageId` | string | uuid4 | 每次随机 |
| `payload.customerId` | string | `"100000001"` | 登录返回 |
| `payload.sourceType` | int | `3` | 读固定 3 |

```json
{
  "lastUpdateTime": 0,
  "accessToken": "1aos...",
  "appVersion": "",
  "openId": "",
  "version": "1.0",
  "deviceType": 2,
  "appType": 100,
  "versionCode": "101",
  "adaptertRank": 720,
  "_": 1792279336082,
  "header": {"messageId": "3f1c8a9e-0000-4000-8000-000000000000"},
  "payload": {"customerId": "100000001", "sourceType": 3}
}
```

### 三条读接口的 `payload` 差异

| 接口 | 追加字段 |
|---|---|
| `/4.0/iot/home/list` | 无 |
| `/4.0/iot/devices/list` | `homeId` |
| `/4.0/iot/devices/detail` | `deviceId`、`partnerId` |

响应结构见 AIHome 文档第二~四节（两者返回体结构一致）。

## 四、空调：状态键与控制命令

这是旧版时代最成熟的部分，也是本集成空调实体的实现依据。

### 状态键（`device.states`）

| 语义 | 键（含容错别名） | 处理 |
|---|---|---|
| 开关机 | `powerStatus` | 布尔 |
| 在线 | `onlineStatus` | 原样 |
| 设定温度 | `setTemperature` / `desiredTemperature` | 数值 |
| 室温 | `realTemperature` / `indoorTemperature` | 数值 |
| 模式 | `modes` / `workMode` / `mode` | `0` 送风、`1` 制热、`2` 制冷、`3` 除湿、`4` 自动 |
| 风速 | `windSpeed`（`autoWind=1` 时视为自动） | `1` 微风、`2` 低、`3` 中、`4` 高 |
| 屏显 | `screenSwitch` | 布尔 |
| 电辅热 | `heatSwitch` | 布尔 |
| 自然风 | `natrueWind` / `natureWind` | 布尔（注意官方拼写 `Natrue`） |
| 自动风 | `autoWind` | 布尔 |
| 左右摆风 | `leftRightWind` | 数值 |
| 左右全摆 | `leftRightWindFullControl` | 布尔 |
| 快速冷暖 | `fastCoolHeatSwitch` | 布尔 |

提示音不在 `states` 里，在 `labels` 中：`labelKey = buzzer_sound`。

### 控制命令

控制体结构与 AIHome 的 `execute` 完全一致（`appType:1`、`sourceType:20`、
`sourceName:"smartlifeAppH5"`），只是命令名不同。

| 动作 | command | params |
|---|---|---|
| 开机 | `connector.device.command.Power` | `{"onAndOff":{"code":"On"}}` ← `sourceName` 用 `smartlifeApp` |
| 关机 | `connector.device.command.Power` | `{"onAndOff":{"code":"Off"}}` |
| 设温 | `connector.device.command.SetTemperature` | `{"setTemperature":{"value":"26"}}` |
| 设风速 | `connector.device.command.SetWindSpeed` | `{"windSpeed":{"value":"3"}}` 或 `{"autoWind":{"value":"1"}}` |
| 设模式 | `connector.device.command.SetModes` | `{"modes":{"value":"2"}}` |
| 屏显 | `connector.device.command.SetScreenSwitch` | `{"screenSwitch":{"value":"1"}}` |
| 电辅热 | `connector.device.command.SetHeatSwitch` | `{"heatSwitch":{"value":"1"}}` |
| 左右全摆 | `connector.device.command.SetLeftRightWindFullControl` | `{"leftRightWindFullControl":{"value":"1"}}` |
| 快速冷暖 | `connector.device.command.SetFastCoolHeatSwitch` | `{"fastCoolHeatSwitch":{"value":"1"}}` |
| 自然风 | `connector.device.command.SetNatrueWind` | `{"natrueWind":{"value":"1"}}` |
| 提示音 | `/4.0/iot/devices/label/batchSave` | 见 AIHome 文档第九节 |

## 五、旧版数组状态格式（已废弃，勿解析）

旧版设备把状态塞在一个**定长逗号数组**里，按固定下标取值：

| 设备 | 数组长度 | 示例 |
|---|---|---|
| 空调 | 210 | `"1,26,28,2,3,0,..."` |
| 冰箱 | 130 | `"6,-16,-40,64,0,0,7,-17,..."` |

现在的响应里它叫 `device.originalState`，**仍然会返回**，但：

1. 下标顺序随固件变化，同一位在不同固件上含义不同；
2. 命名 `states` 已经覆盖全部信息；
3. 数组里有 `-40` 之类哨兵值，无法区分"真实温度"和"未采集"。

因此**只解析 `states`，永远不要解析 `originalState`**。

> 冰箱数组的已知位（仅作排查参考，不作实现依据）：
> `[0]` 冷藏设定、`[1]` 冷冻设定、`[3]` 工作模式编码（`64` 无模式 / `0` 智能 / `65` 速冷）、
> `[4]` 开关、`[11]` 变温档位。

## 六、兼容性说明

| 项 | 结论 |
|---|---|
| 旧域名 `api-wg.hismarttv.com` | 本集成不使用；仅历史实现存在 |
| 旧版 `deviceStatus` 数组 | AIHome 响应里**不存在**该字段（只有 `originalState`） |
| 上游 `d2305d3` 的冰箱 sensor | 依赖 `deviceStatus`，在本机永远为空 —— **不可用** |
| 冰箱实体 | 必须走 AIHome 命名 states，见 [`冰箱开发指南.md`](./冰箱开发指南.md) |
| 洗衣机 / 干衣机 | 走同一 `detail` + `execute` 信封，状态键各自独立 |

### 成功判定

```
httpCode not in (401, 403)  and  payload.status == "SUCCESS"
```

标签接口用另一套：`resultCode`（顶层或 `payload.resultCode`）为 `0` 即成功。
